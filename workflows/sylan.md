# Sylan · Engineering Workflow

我用 Symphony 按工单状态安排实现、审查和返工。

| 工单状态 | 谁来做什么 | 交给下一步 |
| --- | --- | --- |
| Backlog | 主 Session 查上游需求、认领记录和已有 PR，我确定贡献范围 | 一项可独立验收的改动 |
| In Progress | 实现者在独立分支复现问题、修改代码并测试 | 基线、diff、实际运行的命令和结果 |
| Agent Review | 独立审查者对照验收条件检查改动 | 通过后转人工验收，有问题则列出返工项 |
| Human Review / Rework | 我决定接受或返工。实现者按返工项修改，重新送审 | 针对新版本的审查结论 |

**我在哪里介入？** 如果一张 issue 已有人认领，我先看现有 PR 覆盖了什么，再决定是否只做验证。范围已经确定的小改动，下一次通常在人工验收时看到。

## 执行约定

主 Agent 根据任务特征自主选择本生产线的 Skills，不预设固定 Skill Chain，不默认混用其他生产线的 Skills。运行时读取所选 Skill 的原始 SKILL.md，按其要求执行；记录实际加载的 Skill、选择理由、阶段产物、验证命令与结果。事后评估路由是否合理，不以调用数量作为质量目标。

任务分配、模型预算及统一验收细则仍待决策。
